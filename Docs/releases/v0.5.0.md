# LuckySQL v0.5.0

This release adds an AI assistant to the SQL workspace for generating queries, explaining SQL, and repairing failed statements.

- Open the assistant with Command-K, from the editor's AI menu, a table's context menu, or a failed query. Opening it does not send a request; click Send to AI when ready.
- Configure Base URL, API Key, and model under LuckySQL → AI Configuration. OpenAI Chat Completions and Anthropic Messages protocols keep independent settings and support compatible endpoints. A connection test sends a small request without database data.
- Save API keys in a separate macOS Keychain service. Changing the request destination requires entering its key again; secure-storage failures show a notice and retain the key only for the current app session.
- Use selected/referenced table structure and server/session settings as context. Row previews and database credentials are excluded. SQL is optional for generation and required for explanation/repair; review the SQL and error disclosure before sending.
- Review completed suggestions, their explanation and assumptions. Copy SQL, open a new query, or replace the original statement/selection with one undoable edit. AI never executes SQL; existing read-only protection and execution confirmation still apply.
- Keep conversations separate per query tab. Stop cancels the AI request, and changes to drafts, connections, databases or schema metadata prevent applying stale suggestions. Stream errors and interrupted responses cannot become applicable SQL.
- Add Simplified Chinese labels and a compact editor toolbar that keeps the editor and results usable when the assistant is open in a small window.

Validation: 199 tests, 180 passed, 19 optional or external-fixture tests skipped, and 0 failures locally. All 41 new AI tests passed, covering both protocols, streaming/cancellation, configuration and credential isolation, failed-request history, stale suggestions (including literal Unicode changes), native undo and minimum-width layout. Optimized arm64 packaging, bundle signing and checksums were verified; a disposable bundled network probe reached localhost, IPv4 and IPv6 loopback HTTP endpoints. Live provider requests were not tested with a real API key.

Requirements: Apple Silicon and macOS 14 or later. Community builds use ad-hoc signing and are not notarized with Developer ID. AI requests use the configured external service and may incur its usage charges.
