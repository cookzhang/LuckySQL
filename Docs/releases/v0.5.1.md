# LuckySQL v0.5.1

This patch fixes AI conversations losing the original request after a clarification and gives the assistant the table and field descriptions needed to interpret business requirements.

- Keep the original goal and clarification answers when table context is added or refreshed. Answering “which table?” with a real table name loads that table's structure and continues the same conversation.
- Match available table names and descriptions against the current request and earlier answers, retain previously confirmed tables, and include structures together for small schemas. A bounded table catalog helps identify missing tables without reading business rows.
- Include table comments and longer field comments in structured context. Keep readable columns when optional structure metadata is unavailable, and mark omitted/truncated descriptions rather than silently implying complete metadata.
- Store compact conversation turns instead of repeating full schema snapshots in every historical message. Preserve the initial goal when trimming long conversations, while maintaining connection, database, provider and shared-SQL privacy boundaries.
- Show conversation history and the actual loaded table/field descriptions. Clear the composer after sending, restore it after failure or Stop even when the panel was hidden, and scroll to the latest response or request state.
- Prevent a provider change during metadata gathering from sending context derived from the old provider's conversation to the new endpoint. Suggestions still require review and never execute SQL automatically.

Validation: 227 tests, 208 passed, 19 optional or external-fixture tests skipped, and 0 failures locally. The 28 added regressions cover table-name clarification, three-turn repair context, long conversation history, metadata comments, schema-only requests, provider changes and input recovery. Provider responses are simulated; no real API key or live model was used for SQL-quality evaluation.

Requirements: Apple Silicon and macOS 14 or later. Community builds use ad-hoc signing and are not notarized with Developer ID.
