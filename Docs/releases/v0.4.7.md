# LuckySQL v0.4.7

This patch reduces the delay between selecting a table in Data and seeing its rows, and improves filter responsiveness.

- Keep sidebar updates local to the affected rows instead of refreshing the full table list for query progress, result changes, or filter typing.
- Reuse the native data grid and columns while switching tables, and reduce cell layout work.
- Build the visible-column menu when opened, avoiding unnecessary layout for large column lists.
- Keep unapplied filter edits local, avoid reloading an already selected table, and prevent duplicate queries when restoring a table's saved page size.
- Preserve column layout, selection behavior, and table context-menu actions, including copying names and changing favorites during a query.

In a local Release-mode benchmark with 1,000 sidebar tables, 100 result rows, cached metadata, and a simulated 10 ms query, median table-selection-to-first-screen drawing time fell from 383 ms to 174 ms for 40 columns and from 480 ms to 207 ms for 100 columns. These measurements include native layout and drawing; they are not real-database or physical screen-presentation latency guarantees. The query timer measures query work separately from UI updates.

Validation: 152 tests, 133 passed, 19 optional tests skipped, and 0 failures. Additional Release-mode rendering and native context-menu tests passed.

Requirements: Apple Silicon and macOS 14 or later. Community builds use ad-hoc signing and are not notarized with Developer ID.
