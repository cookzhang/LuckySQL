# LuckySQL v0.4.2

This patch makes switching between connection workspaces and SQL query tabs smoother while preserving your place.

- Connection workspaces retain their native editors, result grids, and sidebar state instead of rebuilding the entire interface on every switch. Keyboard focus, selected rows, and scroll positions survive switching back.
- Query tabs reuse their result tables, including column widths, column order, selection, and scrolling. Switching through an empty query preserves the other cached tables. The result-view cache is bounded and releases obsolete results.
- Unchanged SQL keeps its existing syntax highlighting. Draft saves are combined after switching, and rapid tab changes avoid unnecessary completion work.
- Background workspace updates cause fewer unrelated interface refreshes. Hidden editors no longer take keyboard focus, and delayed edits remain associated with the correct query document.
- Both tab bars have larger click targets and keep the selected tab visible when there are many tabs. Connection workspaces have clearer selected styling and localized create/close labels.

Validation: 107 tests passed; 18 optional or external-fixture tests were skipped. Native checks cover switching with a 1,000-row, 40-column result, cached-view retention, empty tabs, new results, draft persistence, and workspace layouts at 1280×800 and 960×640.

Requirements: Apple Silicon and macOS 14 or later. Community builds use ad-hoc signing and are not notarized with Developer ID.
